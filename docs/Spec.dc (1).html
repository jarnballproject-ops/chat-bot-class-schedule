1. บทสรุปสำหรับผู้บริหาร

ระบบนี้แก้ปัญหาที่นักศึกษาต้องเดินไปดูตารางที่ป้ายหน้าภาควิชา หรือทักไปถามอาจารย์เองว่าคาบนี้ว่างไหม โดยให้เจ้าหน้าที่อัปโหลดไฟล์ตารางที่มีอยู่แล้ว (PDF จากระบบทะเบียน รูปถ่าย หรือไฟล์สแกน) ระบบอ่านตารางด้วยโมเดล OCR ที่เชี่ยวชาญเอกสารภาษาไทย แปลงเป็นข้อมูลเชิงสัมพันธ์ แล้วให้นักศึกษาถามเป็นภาษาพูดได้

การตัดสินใจทางสถาปัตยกรรมที่สำคัญที่สุดสองข้อคือ (ก) ไม่ใช้ RAG บนข้อความ OCR ดิบ แต่แปลงเป็นตารางเชิงสัมพันธ์แล้วให้ AI เรียกฟังก์ชันไปดึงด้วย SQL ที่เขียนไว้ล่วงหน้า เพราะข้อมูลตารางสอนตอบผิดไม่ได้ และ (ข) ไม่ใช้ Tesseract แต่ใช้ Vision-Language Model ที่เทรนกับเอกสารไทย เพราะตารางเรียนเป็นโครงตารางหลายชั้นที่ OCR แบบเดิมอ่านลำดับผิด

ปัญหาที่ยากที่สุดของโปรเจกต์นี้ ไม่ใช่ OCR

ในตารางเรียนจริง ช่องหนึ่งมีแต่ ชื่อต้นของครู เช่น "ไมตรี" "ลจี" "ปฐพนพัทธ์" ไม่มีนามสกุลและไม่มีรหัสครู แต่โจทย์ของระบบคือตอบคำถามว่า "อาจารย์คนนี้สอนอะไร" ซึ่งต้องรู้ว่าเป็นตัวคนไหน ถ้าภาควิชามีครูชื่อ "ไมตรี" สองคน ระบบเดาไม่ได้และไม่ควรเดา ระบบจึงต้องมีทะเบียนครูตั้งต้น และมีขั้นตอนให้คนจับคู่ชื่อต้นกับตัวคนหนึ่งครั้ง แล้วจำการจับคู่นั้นไว้ถาวร (ตาราง teacher_alias) หากไม่มีกลไกนี้ ตารางของครูที่ชื่อซ้ำจะปนกันทั้งภาควิชา

5. เกณฑ์วัดความแม่นของ OCR

วัดแบบ field accuracy คือแยกวัดรายฟิลด์ ไม่รวมเป็นตัวเลขเดียว เพราะแต่ละฟิลด์ยากไม่เท่ากันและผลกระทบไม่เท่ากัน: รหัสวิชาเป็นตัวเลขล้วนจึงแม่นสูง ส่วนชื่อครูเป็นภาษาไทยเขียนย่อจึงแม่นต่ำสุดและกระทบมากสุด

field_accuracy(f) = COUNT(ocr_value = human_value WHERE field = f) / COUNT(* WHERE field = f)
— คำนวณจากตาราง field_correction โดยตรง ไม่ต้องทำ dataset แยก

9. Tool ที่ LLM เรียกได้

LLM ไม่เคยเห็นและไม่เคยเขียน SQL — เรียกได้เฉพาะฟังก์ชันชุดปิดนี้ ซึ่งข้างในเป็น SQL แบบ parameterized ที่เขียนไว้ล่วงหน้า วิธีนี้ตัด SQL injection และการ join ผิดออกทั้งคลาส และทำให้ทุกคำตอบตรวจย้อนได้ว่ามาจากแถวไหน

toolพารามิเตอร์ตอบคำถามแบบไหน
{{ tl.name }} {{ tl.args }} {{ tl.q }}
กฎบังคับของชั้นแชท
  1. ห้ามตอบจากความรู้ในตัวโมเดล ทุกคำตอบต้องมาจากผล tool เท่านั้น
  2. ถ้า tool ไม่คืนแถว ต้องบอกว่ายังไม่มีข้อมูลในระบบ ห้ามแต่งคำตอบ
  3. ก่อนส่งคำตอบออก ระบบตรวจว่ารหัสวิชา/ห้อง/เวลาที่ปรากฏในคำตอบมีอยู่ในผล SQL จริง ถ้าไม่มีให้ทิ้งคำตอบและใช้ template แทน
  4. ชื่อต้นที่ชี้ครูได้หลายคน ต้องถามกลับให้ผู้ใช้เลือก ห้ามเดา
  5. ข้อมูลที่ยังไม่ผ่านการตรวจทานตอบได้ แต่ต้องติดป้ายความมั่นใจและลิงก์ดูรูปต้นฉบับทุกครั้ง
  6. คำถามที่ regex จับ pattern ได้ชัดให้ข้ามชั้น LLM ไปเรียก tool ตรงและตอบด้วย template (ต่ำกว่า 300 ms)

15. คำถามที่ยังไม่มีคำตอบ

  1. ทะเบียนครูของภาควิชา — ยังไม่มีไฟล์รายชื่อครูจริง ถ้าไม่ได้ก่อนวันที่ 10 จะสาธิตการจับคู่ชื่อต้นด้วยข้อมูลสมมติ ซึ่งลดน้ำหนักผลการทดลอง
  2. จำนวนกลุ่มเรียนจริง — ยังไม่ทราบ มีผลต่อคำถาม "อาจารย์ว่างช่วงไหน" เพราะต้องอัปโหลดตารางทุกกลุ่มให้ครบก่อนจะตอบได้ถูก ถ้าไม่ครบต้องแสดงคำเตือนว่าข้อมูลอาจไม่สมบูรณ์
  3. SSO ของมหาวิทยาลัย — ยังไม่ทราบว่าเปิด OIDC ให้โปรเจกต์นักศึกษาใช้หรือไม่ แผนสำรองคือ mock provider ในเครื่องพร้อมสวิตช์สลับไปของจริง
  4. ห้องเรียนทั้งหมด — คำถาม "ห้องนี้ว่างไหม" ตอบได้ถูกเฉพาะเมื่อมีรายการห้องครบ ยังต้องขอผังห้องจากภาควิชา
