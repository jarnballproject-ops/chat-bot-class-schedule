# คู่มือสไตล์ — ธีมหลักของระบบ

ธีมนี้ถอดมาจากต้นแบบ `docs/OCR Review - Split.dc (1).html` (หน้าตรวจทานผล OCR) แล้วใช้เป็นธีมกลาง
ของทุกหน้าในระบบ โค้ดจริงอยู่ที่ `frontend/src/theme.css` ส่วนไฟล์นี้อธิบายว่าทำไมและใช้ยังไง

> **ที่มาของค่าสี** — ไฟล์ต้นแบบอ้าง CSS ของ design system ชื่อ `industry` ที่
> `_ds/industry-.../styles.css` ซึ่งไม่ได้ถูกเซฟมาด้วย ค่าสีในธีมนี้จึงถอดจากภาพที่ render แล้ว
> ไม่ได้คัดลอกจากไฟล์ต้นฉบับ ถ้าภายหลัง export ไฟล์นั้นออกมาได้ ให้แทนค่าใน `:root` ของ
> `theme.css` ทีเดียวจบ ส่วนอื่นไม่ต้องแก้เพราะทุกที่อ้าง token ไม่มีที่ไหน hardcode สี

## 1. หลักคิดของธีม

**สีเดียวทั้งระบบ** — น้ำเงินเหล็ก `--color-accent` ที่เหลือเป็นขาว เทา ดำ สีน้ำเงินถูกสงวนไว้
สำหรับสองอย่างเท่านั้น: สิ่งที่กดได้ และสิ่งที่ต้องการให้คนสนใจ ถ้าเอาน้ำเงินไปใช้ตกแต่ง
ความหมายนี้จะเจือจางจนใช้ชี้อะไรไม่ได้อีก

**เส้นบางแทนเงา** — ทุกการแบ่งพื้นที่ใช้เส้น 1px สี `--color-divider` ไม่ใช้ `box-shadow`
ตกแต่งและไม่ใช้มุมมนใหญ่ ทั้งระบบใช้ `--radius: 3px` ค่าเดียว

**ความหนาแน่นสูง** — หน้าจอนี้มีไว้ให้เจ้าหน้าที่ทำงานกับข้อมูลจำนวนมากต่อเนื่องหลายชั่วโมง
ระยะห่างจึงแน่น ตัวอักษรฐาน 14px ป้ายกำกับ 10–12px ไม่ใช่หน้า marketing ที่ต้องโปร่ง

**ป้ายกำกับเล็กตัวพิมพ์ใหญ่เว้นระยะ** — `.meta-label` และ `.eyebrow` ใช้ `text-transform: uppercase`
กับ `letter-spacing` เพราะเป็นภาษาของแบบวิศวกรรมและฟอร์มราชการ ซึ่งเป็นบริบทของงานนี้
(กติกานี้ขัดกับคำแนะนำทั่วไปที่ให้เลี่ยง ALL CAPS แต่ที่นี่ยึดตามต้นแบบ)

### ตัวอักษร

`--font: "Noto Sans Thai", Barlow, system-ui, sans-serif` — ฟอนต์เดียวทั้งระบบ ไม่มีฟอนต์หัวเรื่องแยก

|---|---|
| 17px / 600 | หัวเรื่องหน้า |
| 16px / 600 | หัวเรื่องพาเนล |
| 14px / 600 | ค่าในแถบ meta |
| 14px / 400 | เนื้อความทั่วไป |
| 13px | ปุ่ม ช่องกรอก |
| 11–12px | ป้ายกำกับ ข้อความอธิบาย |
| 9–10px | ไม้บรรทัดเวลา ป้ายกำกับตัวพิมพ์ใหญ่ |

## 3. คอมโพเนนต์

### โครงหน้า (app shell)

```html
<div class="shell">
  <nav class="rail">…นำทาง + บทบาท…</nav>
  <div class="shell__body">
    <header class="topbar">…</header>
    <main class="workspace">
      <aside class="pane pane--registry">…ทะเบียนครู…</aside>
      <section class="pane pane--work">…งานหลักของหน้า…</section>
      <aside class="pane pane--inspector">…สิ่งที่เลือกอยู่…</aside>
    </main>
  </div>
</div>
```

ทุกหน้าใช้โครงเดียวกัน ต่างกันแค่ว่ามีคอลัมน์ไหนบ้าง `rail` กับ `topbar` ไม่เลื่อนตามเนื้อหา
เพราะ `.shell` สูงเท่าจอพอดีแล้วให้แต่ละคอลัมน์เลื่อนของตัวเอง (`.pane--work`, `.people`,
`.pane--inspector`) — ตารางที่กว้างกว่าจอเลื่อนแนวนอนในกล่อง `.scroller` ไม่ใช่ทั้งหน้า

| ส่วน | ใช้เมื่อ |
|---|---|
| `pane--registry` | หน้าที่ต้องเลือก "ทำงานกับใคร" ก่อน — เลือกค้างไว้ข้ามหน้าได้ ห้ามทำ dropdown ซ้ำในหน้าอื่น |
| `pane--work` | งานหลักของหน้านั้น พื้นหลังเป็น `--color-bg` เพื่อให้แผงขาวสองข้างเด่นขึ้น |
| `pane--inspector` | รายละเอียด/ฟอร์มแก้ของสิ่งที่เลือกอยู่ กว้าง 368px ฟิลด์เรียงลงทีละอัน |

จอแคบกว่า 1240px แผง inspector ลงไปอยู่ใต้เนื้อหา · แคบกว่า 900px `rail` กลายเป็นแถวบนสุด

ทุกตัวอยู่ใน `theme.css` แล้ว เรียกใช้ด้วยชื่อคลาสตรง ๆ ไม่ต้องเขียน CSS ใหม่

### ปุ่ม

```html
<button class="btn btn-primary">ยืนยันและบันทึกเข้าฐานข้อมูล</button>
<button class="btn btn-secondary">ช่องถัดไปที่ต้องตรวจ</button>
<button class="btn btn-ghost">คืนค่าเดิมจาก OCR</button>
```

**กติกา: `btn-primary` ได้หน้าละหนึ่งปุ่มเท่านั้น** คือการกระทำที่ทำให้งานของหน้านั้นจบ
ถ้ามีสองปุ่มน้ำเงินบนหน้าเดียว แปลว่ายังตัดสินใจไม่ได้ว่าหน้านั้นมีไว้ทำอะไร
`btn-secondary` คือทางเลือกรอง `btn-ghost` คือคำสั่งที่ย้อนกลับได้หรือไม่สำคัญ

ข้อความบนปุ่มบอกสิ่งที่จะเกิดขึ้น ไม่ใช่ "ตกลง" หรือ "ส่ง" และต้องใช้คำเดียวกันตลอดทั้งขั้นตอน

### ฟิลด์

```html
<div class="field">
  <label for="room">ห้อง · 93%</label>
  <input id="room" class="input" />
</div>
```

ป้ายกำกับอยู่เหนือช่องเสมอ ไม่วางข้าง ถ้ามีค่าความมั่นใจจาก OCR ให้ต่อท้ายป้ายด้วย ` · NN%`
ช่องที่อ่านอย่างเดียวใส่ `readOnly` แล้วธีมจะเปลี่ยนพื้นเป็นเทาอ่อนให้เอง

ถ้าสิ่งที่อยู่ใต้ป้ายไม่ใช่ control เดี่ยว (เช่น กลุ่มปุ่มเพิ่ม/ลด หรือ segmented control)
ห้ามใช้ `<label>` เพราะไม่มี `for` ให้ชี้ ใช้ `<span class="field-label" id="...">` แล้วผูกด้วย
`aria-labelledby` ที่กลุ่มแทน

```html
<div class="field">
  <span class="field-label" id="span-label">จำนวนคาบต่อเนื่อง</span>
  <div class="stepper" role="group" aria-labelledby="span-label">…</div>
</div>
```

### ซ่อนจากตาแต่ไม่ซ่อนจากเครื่องอ่านหน้าจอ

`input[type=file]` ที่มีพื้นที่ลากวางเป็นหน้ากาก ห้ามซ่อนด้วย `display: none` เพราะจะโฟกัสด้วย Tab
ไม่ได้เลย ใช้คลาส `.sr-only` แทน แล้วให้ตัวครอบแสดงกรอบโฟกัสด้วย `:focus-within`

### Segmented control

```html
<div class="seg" role="radiogroup" aria-label="ประเภทคาบ">
  <label class="seg-opt"><input type="radio" name="kind" /><span>ทฤษฎี</span></label>
  <label class="seg-opt"><input type="radio" name="kind" /><span>ปฏิบัติ</span></label>
</div>
```

ใช้เมื่อตัวเลือกมี 2–4 ตัวและต้องเห็นทุกตัวพร้อมกัน ถ้ามากกว่านั้นใช้ `select.input`

### พาเนล blueprint

```html
<div class="blueprint detail">
  <i class="corner tl" /><i class="corner tr" /><i class="corner bl" /><i class="corner br" />
  ...
</div>
```

เครื่องหมายบวกสี่มุมบอกขอบเขตของพื้นที่ทำงาน ใช้กับพาเนลที่ผู้ใช้ต้องลงมือทำอะไรบางอย่าง
**อย่าใช้กับพื้นที่ที่มีไว้อ่านอย่างเดียว** ไม่งั้นเครื่องหมายมุมจะกลายเป็นของประดับ

### แถบหัวและแถบ meta

```html
<header class="topbar">
  <span class="eyebrow">ก · ตารางสอน</span>
  <h1 class="topbar__title">ตารางสอนรายอาจารย์</h1>
  <div class="topbar__right">…</div>
</header>

<div class="metastrip">
  <div class="metastrip__item">
    <div class="meta-label">ภาคเรียน</div>
    <div class="meta-value">1/2569</div>
  </div>
</div>
```

`eyebrow` มีได้หน้าละอันเดียว บอกว่าหน้านี้อยู่ขั้นไหนของกระบวนการ (ก, ข, ค … ตามลำดับงาน)
`metastrip` ใส่ได้ 4–6 ช่อง เกินกว่านั้นคนกวาดตาไม่ทัน ช่องสุดท้ายเป็นคำใบ้สีน้ำเงินได้

## 4. การเข้ารหัสความหมายด้วยสายตา

ธีมนี้มีสีเดียว จึงต้องใช้ **รูปทรงและคำนำหน้า** แยกความหมาย ไม่ใช่เพิ่มสี

| ความหมาย | วิธีแสดง |
|---|---|
| คาบปฏิบัติ | การ์ดพื้น `--color-accent-200` + รหัสขึ้นต้น `ป.` |
| คาบทฤษฎี | การ์ดพื้นขาว + รหัสขึ้นต้น `ท.` |
| สิ่งที่เลือกอยู่ | ขอบ `--color-accent-800` + `box-shadow: inset 0 0 0 1px` |
| ถูกแก้ด้วยมือ | ขอบประ `1px dashed` |
| ความมั่นใจ OCR < 70% | พื้น `--color-accent-300` |
| ความมั่นใจ OCR 70–85% | พื้น `--color-accent-100` |
| ความมั่นใจ OCR > 85% | พื้นโปร่ง ขอบปกติ |

**ทุกอย่างที่สื่อด้วยสีต้องสื่อด้วยอย่างอื่นซ้ำอีกทางเสมอ** คาบปฏิบัติไม่ได้แยกด้วยพื้นสีอย่างเดียว
แต่มี `ป.` นำหน้ารหัสด้วย คนตาบอดสีจึงยังอ่านตารางได้ และต้องมีคำอธิบายสัญลักษณ์ (`.legend`)
กำกับทุกครั้งที่ใช้การเข้ารหัสพวกนี้

## 5. กติกาเขียนข้อความ

- ใช้ภาษาที่ผู้ใช้พูด ไม่ใช่ภาษาที่ระบบใช้ — "ทะเบียนครู" ไม่ใช่ "teacher registry"
- สถานะว่างต้องบอกว่าต้องทำอะไรต่อ ไม่ใช่บอกแค่ว่าไม่มีข้อมูล
  ตัวอย่างที่ใช้จริง: "ตารางจะขึ้นที่นี่หลังเจ้าหน้าที่อัปโหลดไฟล์ตารางของภาคเรียนนี้และกดเผยแพร่แล้ว"
- ข้อความ error มาจาก `detail` ของ problem+json ที่ backend ส่งมา ไม่ต้องเขียนทับที่ฝั่งหน้าเว็บ
  เพราะจะได้ข้อความเดียวกันทั้งตอนเรียกผ่านหน้าเว็บและผ่าน API
- ไม่ขอโทษ ไม่คลุมเครือ บอกว่าอะไรเกิดขึ้นและแก้ยังไง

## 6. เพิ่มหน้าใหม่ต้องทำอะไรบ้าง

1. `@import "./theme.css"` แล้วใช้ token ห้ามใส่ค่าสีตรง ๆ
2. วางในโครง `.shell` ที่มีอยู่แล้ว เพิ่มรายการใน `rail` หนึ่งบรรทัด แล้ววางเนื้อหาใน `.pane--work`
   `.topbar` มี eyebrow (บอกว่าเป็นขั้นไหนของงาน) + ชื่อหน้า + การกระทำหลัก ตามด้วย `.metastrip` ถ้ามีบริบทที่ต้องรู้
3. งานที่ต้องลงมือทำอยู่ใน `.blueprint` งานที่มีไว้อ่านอยู่ใน `.pane` ธรรมดา
4. `btn-primary` หนึ่งปุ่ม
5. ทุกสถานะต้องออกแบบครบสี่แบบ: กำลังโหลด · มีข้อมูล · ว่าง · ผิดพลาด
6. ทดสอบที่ความกว้าง 390px ด้วย ตารางให้เลื่อนแนวนอนได้ อย่าบีบคอลัมน์จนอ่านไม่ออก
7. ต้องเห็นกรอบโฟกัสตอนกด Tab และต้องเคารพ `prefers-reduced-motion` (ธีมจัดการให้แล้ว)
8. เนื้อหาหลักของหน้าอยู่ใน `<main>` หนึ่งตัว ชื่อหน้าเป็น `<h1>` หนึ่งตัว ข้อความผิดพลาดใส่ `role="alert"`
   ผลลัพธ์ที่สำเร็จใส่ `role="status"` ไม่งั้นคนที่ใช้เครื่องอ่านหน้าจอไม่รู้ว่าเกิดอะไรขึ้น
9. การกระทำที่ทำได้ด้วยเมาส์อย่างเดียว (เช่น ลากวางคาบ) ต้องมีทางทำแบบเดียวกันด้วยคีย์บอร์ดเสมอ
   ในหน้าตารางคือฟอร์มแก้วัน/คาบใต้ตาราง
10. ตรวจด้วย axe-core ก่อนปิดงาน ต้องเหลือ 0 violation (รวมกฎ best-practice)
